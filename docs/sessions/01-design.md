# Session 01 — Visual design before controller connection

## Prompt

Work in boxing-game. Read PRODUCT.md and docs/DESIGN-BRIEF.md. Focus on the visual experience first. Use Impeccable to resolve the design with the user, preserving the agreed semi-LEGO toy fighters, Marvel-comic-inspired lettering, continuous fight and behind/above-player camera. Do not repeat settled combat questions.

Clarify only the remaining visual decisions: illustrated concept frames versus a browser design prototype, fighter identities/silhouettes, and atmosphere of the first ring. Label any unselected option as proposed. Keep the original palette-role and toy/comic direction open to a more specific visual treatment; do not copy Signal Lock's interface as the boxing design.

Create concrete reviewable designs for the main fighting screen and its important moments: ready/entrance, readable normal combat, impactful counter/stagger, Super ready/active, pause and victory/loss. Define fighter proportions/materials, arena staging, camera composition, health/stamina/Super hierarchy, Attack/Stance/Power strip, comic typography and sound/motion intent. Lettering should be exuberant without hiding tells or meters. Establish a limited reusable visual system, not a collection of unrelated effects.

When illustrated frames are chosen, use them to settle composition/art direction before application code. When a browser prototype is chosen, keyboard/pointer controls may demonstrate selected punches, stance, power and presentation, with clear labelling if combat outcomes are illustrative. Design approval must not depend on connecting the ESP32. Keep hardware/baseline and existing controller code unchanged during this session.

## Acceptance

- The user can assess actual fighter/arena/screen visuals, rather than only a written style description.
- All agreed controls have clear readable selections and feedback.
- Continuous combat remains visually legible, including during comic effects.
- Reduced-motion and laptop/responsive constraints are reflected in the design.
- The chosen world, composition and unresolved tuning questions are explicitly recorded.
- Controller wiring, button firmware and input relay are deferred to session 02.

## Handoff

Approved design direction, concept-frame or browser-prototype locations, asset provenance, selected fighter/arena treatment, motion examples, first-viewport composition and the exact visual contract for session 05. Do not claim a design prototype has complete combat or hardware integration unless those features were implemented and tested.
